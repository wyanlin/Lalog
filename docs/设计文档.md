## 1. 项目概述

### 1.1 项目名称
LynxLog — 基于 Windows 的 Android 设备日志实时抓取与筛选工具。

### 1.2 项目目标
通过 ADB 连接 Android 设备，实时抓取并展示 logcat 日志，支持关键字筛选（含大小写匹配、正则表达式）。提供日志分析页，对卫星通信 AT 指令进行解析，支持状态/语音/数据分域展示、导出与图表，为开发和调试提供便捷的日志查看与分析能力。

### 1.3 运行环境
| 环境项 | 说明 |
|--------|------|
| 操作系统 | Windows 10/11 |
| Python | 3.8+ |
| GUI 框架 | PyQt5 5.15+ |
| 外部依赖 | ADB（Android Debug Bridge），已安装并加入 PATH |
| 目标设备 | 通过 USB 或 WiFi 连接的 Android 设备（需开启开发者选项与 USB 调试） |

### 2.2 功能详细说明

#### F1：设备选择与刷新

| 需求项 | 描述 |
|--------|------|
| F1.1 设备列表 | 下拉框（ComboBox）展示当前通过 `adb devices` 获取的已连接设备列表 |
| F1.2 设备信息 | 每个选项显示设备标识（如序列号或 IP:端口），便于区分多设备 |
| F1.3 刷新设备 | 提供「刷新设备」按钮，点击后重新执行 `adb devices` 并更新列表 |
| F1.4 无设备状态 | 若无可选设备，下拉框为空或显示「无设备」，开始抓取按钮应禁用或给出提示 |

**交互流程**：
1. 程序启动时自动执行一次设备扫描；
2. 用户点击「刷新设备」可重新扫描；
3. 用户从下拉框中选择目标设备。

---

#### F2：实时日志抓取

| 需求项 | 描述 |
|--------|------|
| F2.1 开始抓取 | 点击「开始抓取」后，对当前所选设备执行 `adb -s <device_id> logcat -v time`，持续读取 stdout |
| F2.2 停止抓取 | 点击「停止抓取」后，终止 logcat 子进程，停止接收新日志 |
| F2.3 实时显示 | 每收到一行 logcat 输出，立即追加到主界面日志区域，并自动滚动到最新一行 |
| F2.4 状态反馈 | 抓取中时，可通过按钮状态（如「开始」禁用、「停止」启用）或状态栏提示当前状态 |
| F2.5 防重入 | 正在抓取时禁止再次点击「开始抓取」；未抓取时禁止点击「停止抓取」 |

**交互流程**：
1. 用户选择设备；
2. 用户点击「开始抓取」；
3. 程序启动 logcat 子进程，将输出写入日志区域；
4. 用户点击「停止抓取」停止进程。

---

#### F3：关键字筛选设置

| 需求项 | 描述 |
|--------|------|
| F3.1 关键字输入 | 提供单行输入框，用户输入筛选关键字 |
| F3.2 匹配大小写 | 提供勾选框「匹配大小写」，勾选时按大小写敏感匹配，否则不敏感 |
| F3.3 正则表达式 | 提供勾选框「正则表达式」，勾选时按正则表达式匹配，否则按普通字符串包含匹配 |
| F3.4 可随时修改 | 筛选条件可在抓取前或抓取中修改，修改后对后续新日志立即生效 |
| F3.5 空关键字 | 关键字为空时，不做筛选，显示全部日志 |

**筛选逻辑**：
- 关键字为空 → 显示所有日志；
- 关键字非空 → 仅显示满足条件的日志行；
- 条件：包含匹配 / 正则匹配，并结合「匹配大小写」决定是否区分大小写。

---

#### F4：筛选与抓取联动

| 需求项 | 描述 |
|--------|------|
| F4.1 先设筛选后抓取 | 用户可先设置关键字和选项，再点击「开始抓取」，此时只显示通过筛选的日志 |
| F4.2 抓取中改筛选 | 抓取过程中修改筛选条件，对已显示内容不回溯，仅影响新到达的日志行 |
| F4.3 筛选执行位置 | 在应用层对每行日志进行筛选，不修改 adb logcat 命令参数，保证原始数据源一致 |

**数据流**：
```
adb logcat (stdout) → 按行读取 → 应用层筛选 → 通过则追加到 UI
```

---

#### F5：日志分析（AT 指令解析）

| 需求项 | 描述 |
|--------|------|
| F5.1 解析方案 | 工具栏提供解析方案下拉（天通/星网等），选择后按对应制式的 AT 规则解析 |
| F5.2 模组选择 | 模组下拉（通用/06A/1881），同一 chip 在天通与星网下可适用不同 AT 指令 |
| F5.3 AT 解析 | 按 `urc_prefix` 匹配 URC 行，按 `separator` 拆分字段，经 decoder 解码后展示 |
| F5.4 分域展示 | 结果区按 status/voice/data 三域分 Tab 展示，支持实时过滤、导出 CSV/Excel、图表 |
| F5.5 可扩展 | 规则与解码器通过 JSON 配置 + 代码注册，支持 system/module 级覆盖 |
| F5.6 指令类型 | 每条规则配置 `category`（与 MSC06A 手册章节对应：通用控制、网络服务、呼叫控制等）；解析结果表增加「类型」列；工具栏提供「指令类型」勾选框，可按类型显示/隐藏行，与关键字过滤同时生效 |

**层级与合并顺序**：
```
base.json（通用规则）
    → modules/<chip>.delta.json（芯片级差异）
    → systems/<system>.json（制式级差异，最终生效）
```
同一芯片（如 06A）在天通与星网下 AT 指令可能不同，制式级 rules_override 覆盖芯片级。

**当前内置规则**：`cpstate`（^CPSTATE）、`satsignal`（^SATSIGNAL）。

## 3. 技术架构

### 3.1 整体架构

```
┌─────────────────────────────────────────────────────────────────┐
│                         PyQt5 GUI Layer                          │
│  MainWindow / DeviceSelector / LogViewer / FilterPanel           │
│  LogAnalysisTab（解析方案/模组选择、指令类型筛选、分域表格、导出、图表）│
└────────────────────────────────────────┬────────────────────────┘
                                         │ 信号/槽
┌────────────────────────────────────────┴────────────────────────┐
│                     Business Logic Layer                         │
│  AdbManager（设备、进程） / LogFilter（筛选逻辑）                   │
│  log_analysis.engine / config_loader / categories / decoders      │
└────────────────────────────────────────┬────────────────────────┘
                                         │ subprocess
┌────────────────────────────────────────┴────────────────────────┐
│                        External Layer                            │
│  ADB (adb.exe) / Android Device                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 模块划分

| 模块 | 职责 | 主要接口 |
|------|------|----------|
| **AdbManager** | 执行 adb 命令、管理设备列表、启动/停止 logcat 子进程 | `get_devices()`, `start_logcat(device_id)`, `stop_logcat()` |
| **LogFilter** | 根据关键字、大小写、正则对单行日志进行匹配 | `matches(line, keyword, case_sensitive, use_regex) -> bool` |
| **log_analysis.engine** | 按 EffectiveProfile 逐行解析 AT/URC，产出 ParsedAtRecord | `parse_log(text, system_id, module_id)` |
| **log_analysis.config_loader** | 合并 base + module + system 配置，返回 EffectiveProfile | `load_profile()`, `list_systems()`, `list_modules()` |
| **log_analysis.categories** | AT 手册章节类型 id 与中文名（`CATEGORY_DEFS`） | `label_for(category_id)` |
| **log_analysis.decoders** | 注册解码器，对原始字段值做映射或格式化 | `decode(name, value)` |
| **MainWindow** | 主窗口布局，协调各子控件与业务逻辑 | — |
| **DevicePanel** | 设备下拉框、刷新按钮 | 信号：`device_selected`, `refresh_clicked` |
| **FilterPanel** | 关键字输入、匹配大小写、正则勾选 | 信号：`filter_changed` |
| **LogPanel** | 日志文本显示、追加、滚动 | 方法：`append_line()`, `clear()` |
| **ControlPanel** | 开始/停止抓取按钮 | 信号：`start_clicked`, `stop_clicked` |
| **LogAnalysisTab** | 解析方案/模组、指令类型勾选、分域表格、导出、图表 | — |

### 3.3 数据流

```
[用户选择设备] ──→ AdbManager.get_devices()
                       │
[用户点击开始] ──→ AdbManager.start_logcat(device_id)
                       │
                       ▼
              subprocess.Popen(adb logcat ...)
                       │
                       ▼
              QThread 读取 stdout 逐行
                       │
                       ▼
              LogFilter.matches(line, keyword, ...)
                       │
              通过 ──→ LogPanel.append_line(line)
              不通过 ──→ 丢弃
```

## 5. 核心实现要点

### 5.1 ADB 命令

```bash
# 获取设备列表
adb devices -l

# 实时 logcat（输出格式：time）
adb -s <device_id> logcat -v time
```

解析 `adb devices` 输出：每行格式为 `序列号\tdevice` 或 `IP:端口\tdevice`，跳过首行 "List of devices attached" 和空行。

### 5.2 异步读取 logcat

- 使用 `QThread` + `QProcess` 或 `subprocess.Popen` 在后台线程中读取 stdout；
- 每读一行，通过信号 `line_received(str)` 发送到主线程；
- 主线程槽函数中调用 `LogFilter.matches()`，通过则 `LogPanel.append_line()`；
- 避免在 UI 线程中执行阻塞 I/O。

### 5.3 筛选逻辑伪代码

```python
def matches(line: str, keyword: str, case_sensitive: bool, use_regex: bool) -> bool:
    if not keyword:
        return True
    if use_regex:
        flags = 0 if case_sensitive else re.IGNORECASE
        try:
            return bool(re.search(keyword, line, flags))
        except re.error:
            return False  # 非法正则，可考虑提示用户
    else:
        if case_sensitive:
            return keyword in line
        return keyword.lower() in line.lower()
```

### 5.4 进程终止

- 使用 `process.terminate()` 或 `process.kill()` 停止 logcat；
- 在 `stop_logcat()` 中确保进程已结束，避免僵尸进程。

### 5.5 日志分析配置与 AT 解析

**配置目录结构**：
```
src/ui/log_analysis/config/
├── base.json           # 通用规则集（cpstate、satsignal 等）
├── systems/
│   ├── tiantong.json   # 天通制式：tags RIL_TT-AT，modules generic/06a/1881
│   └── xingwang.json   # 星网制式：tags RIL_L-AT，modules generic/06a/1881
└── modules/
    ├── 06a.delta.json  # 06A 芯片级 rules_override（制式覆盖本层）
    └── 1881.delta.json # 1881 芯片级 rules_override
```

**规则合并顺序**（后者覆盖前者同 id 规则）：
1. `base.json` — 通用规则集；
2. `modules/<module>.delta.json` — 芯片级差异（module=generic 时跳过）；
3. `systems/<system>.json` — 制式级差异，同一 chip 在天通/星网下 AT 可不同。

**规则定义格式**（RuleDef）：
| 字段 | 说明 |
|------|------|
| id | 规则唯一标识 |
| domain | status / voice / data |
| category | 手册章节类型 id（见 `categories.py` 中 `CATEGORY_DEFS`，与 MSC06A 第 3～9 章及「状态监控」对应），用于界面筛选与「类型」列展示 |
| urc_prefix | 行内匹配前缀（如 `^CPSTATE:`） |
| separator | 字段分隔符，默认 `,` |
| columns | [{ key, label, decoder?, numeric }] |

**解码器**：在 `decoders/registry.py` 中通过 `@register("name")` 注册，对原始值做映射（如 mm_state 码表、0→无效 等）。

**类型定义**：`src/ui/log_analysis/categories.py` 提供 `CATEGORY_DEFS`（id 与中文显示名）。

## 7. 开发与测试建议

1. **单元测试**：对 `LogFilter.matches()` 编写用例，覆盖空关键字、大小写、正则、非法正则等情况。
2. **设备测试**：准备至少一台真机或模拟器，验证多设备切换、无设备时的表现。
3. **性能**：日志量过大时，可考虑限制显示行数（如保留最近 N 行）或分页，避免内存与 UI 卡顿。
4. **异常处理**：ADB 不可用、设备断开、logcat 异常退出时，应有明确提示并恢复按钮状态。

## 8. 附录：adb logcat 输出格式示例

```
03-09 10:30:01.123  1234  1234 I TagName: This is a log message
```
- 日期时间 | PID | TID | 级别 | Tag | 消息内容

筛选时针对整行字符串进行匹配，可同时匹配 Tag 和消息内容。
